# 啪叽 Paji 策划案

> 把你的角色捏成会动的表情包。
> 文档状态：v0.1（立项稿）· 2026-11-16

## 1. 一句话定位

上传一张角色图，AI 导演把它变成一个 3D 小演员；你说一句"裂开"，它就演给你看，然后导出 GIF 发到群里。

"啪叽"是软东西拍在地上的声音，也是本项目的美学立场：**挤压、拉伸、弹跳，越不正经越好。**

## 2. 趣味性从哪里来

表情包好笑，从来不是因为建模精细或动作真实，而是因为三件事。整个产品的取舍都从这三条推出来。

| 笑点来源 | 含义 | 对产品的要求 |
| --- | --- | --- |
| 夸张 | 情绪被放大到物理上不合理 | 动作系统以"挤压拉伸、震动、怼脸"为一等公民，而不是骨骼写实动作 |
| 反差 | 一本正经地做蠢事 | AI 以"严肃导演"的口吻指挥一个傻乎乎的演员 |
| 即时 | 想到就能发 | 从输入一句话到看到预览，要快到能连续试错 |

由此得到三条设计原则：

1. **情绪优先，不是动作优先。** 用户输入的是"无语""收到""下班了"，不是"向左转 30 度"。把情绪翻译成动作是 AI 的活。
2. **粗糙是特性，不是缺陷。** 3D 模型只需"大致像"，再用卡通描边和果冻物理把瑕疵变成丑萌。
3. **等待即内容。** 生成模型和动画都要等，等待期间导演在说话、演员在候场，不出现空白进度条。

## 3. 核心体验：片场四幕

整个流程用"片场"做隐喻，用户是制片人，AI 是导演，上传的角色是演员。

### 第一幕 · 选角（上传）

- 拖入一张角色图（立绘、头像、手绘草稿都行）。
- 导演立刻看图发言，先夸后损地点评角色（"这位演员的眼神里有三分疲惫，很适合演打工人"），同时后台开始生成 3D 模型。
- 这段点评就是等待期间的内容，约一分钟的生成时间不再是空白。

### 第二幕 · 定妆（3D 模型审阅）

- 模型出现在转台上，自带卡通描边和待机呼吸动画，一出场就是活的。
- 导演给出一份"出厂质检报告"：自己从四个角度看了模型，对照原图说明哪里像、哪里歪了。
- 用户可以做三件事：
  - **通过**：进入开拍。
  - **重捏**：重新生成一版。
  - **整形**：拖动"大头""短腿""胖瘦"滑条，把角色 Q 版化。这是纯本地变形，实时生效，不消耗生成额度。

### 第三幕 · 开拍（给动作，出动画）

- 输入一句话，或点一个语义快捷词：`收到` `谢谢老板` `裂开` `无语` `摸鱼` `下班了` `已读不回` `我没事`。
- 导演一次交出 **三条**：正常版、夸张版、发疯版。三条并排循环播放，点哪条用哪条。
- 微调不需要再问 AI：
  - **夸张度旋钮**，刻度 0 到 11，实时缩放所有动作幅度。
  - **速度**、**字幕文字**、**特效开关**，都是本地即时生效。
- 想改大方向就直接跟导演说（"再崩溃一点""最后飞出画面"），导演在原有动作上改，不是从头来。
- 导演在生成过程中持续喊话（"第二条，情绪再饱满一点！"），工具调用过程就是表演的一部分。

### 第四幕 · 杀青（导出）

- 选平台预设（尺寸和体积预算不同），一键导出透明底或纯色底 GIF。
- 导出的 GIF 保证首尾无缝循环。
- 同一个演员的多条表情自动收进"作品集"，可继续加拍。

## 4. 趣味机制清单

按"投入产出比"排序，前五项进入首个可玩版本。

| 优先级 | 机制 | 为什么好玩 |
| --- | --- | --- |
| P0 | 一次三条（正常 / 夸张 / 发疯） | 选择本身就是乐趣，发疯版负责制造意外 |
| P0 | 夸张度旋钮（调到 11） | 零延迟的操控感，用户亲手把动作玩坏 |
| P0 | 果冻物理（自动的弹性余震） | 任何粗糙动作加上余震都会显得有生命 |
| P0 | 特效贴纸（汗滴、问号、爱心、黑线、速度线、冲击星） | 表情包的通用语言，挂在角色头顶即可 |
| P0 | 动态字幕（抖动、弹出、逐字砸下） | 文字是表情包的另一半 |
| P1 | 导演人设与喊话 | 把等待变成内容，把工具变成角色 |
| P1 | Q 版整形滑条 | 让用户在审阅阶段就开始玩 |
| P2 | 花絮（NG 镜头，演员演砸的版本） | 意外之喜，适合分享 |
| P2 | 一键成套（按语义列表批量拍 8 条） | 从单个表情升级到表情包 |

## 5. 动作语言

表情包的动作可以拆成四层，每一层都不依赖骨骼绑定：

| 层 | 内容 | 例子 |
| --- | --- | --- |
| 整体运动 | 位移、旋转、缩放 | 弹跳、转圈、疯狂摇头、飞出画面、倒地 |
| 形变 | 挤压拉伸、弯曲、扭转、果冻抖动 | 被压扁、气到膨胀、点头哈腰、瑟瑟发抖 |
| 镜头 | 推拉、震屏、倾斜 | 怼脸放大、冲击震动、荷兰角 |
| 贴片 | 特效贴纸、字幕 | 汗滴、问号、"收到" |

绝大多数流行表情包只用到这四层。四肢级别的动作（挥手、跳舞）需要骨骼，作为后续扩展，不进入首版。

## 6. 范围

### 首版包含

- 单角色，单张原型图。
- 四幕完整流程。
- 上表中的 P0 机制。
- GIF 导出，含透明底。
- 作品保存在浏览器本地。

### 明确不做

- 账号、云端同步、社区、付费。
- 写实动作、动捕、多角色同框。
- 视频或其他格式导出。
- 模型的手工编辑（顶点、贴图）。

## 7. 成功标准

| 指标 | 目标 |
| --- | --- |
| 从上传到第一个 GIF 的时间 | 3 分钟以内 |
| 输入动作到看见三条预览 | 15 秒以内 |
| 每个角色平均导出数 | 3 个以上 |
| 主观标准 | 新用户在第一次看到预览的 30 秒内笑出来 |

## 8. 风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 生成的 3D 模型不像原图 | 第二幕体验崩塌 | 卡通描边统一风格；允许重捏；质检报告主动承认瑕疵并把它说成特点 |
| AI 生成的动作平庸 | 不好笑 | 动作词汇表预置夸张参数；发疯版强制使用极端值；夸张度旋钮兜底 |
| 用户上传真人或他人版权角色 | 合规 | 上传时提示仅用于个人创作；图片会发送给第三方生成服务，需明示 |
| 生成成本 | 不可持续 | 整形和微调全部本地完成；模型按角色缓存，一个角色只生成一次 |

## 9. 里程碑

| 阶段 | 交付 | 验收 |
| --- | --- | --- |
| M0 技术验证 | 三个高风险点各跑通一个最小样例 | 见技术选型文档第 8 节 |
| M1 舞台 | 内置样例模型 + 动作语言 + GIF 导出，无 AI | 手写一份动作谱能导出无缝循环的透明 GIF |
| M2 选角与定妆 | 上传、生成、审阅、整形 | 任意角色图能走到"通过" |
| M3 导演 | AI 导演、一次三条、对话修改 | 输入"裂开"得到三条可用预览 |
| M4 打磨 | 特效贴纸、字幕、旋钮、导演喊话、平台预设 | 达到第 7 节的成功标准 |
| M5 可选 | 骨骼动作 | 人形角色能挥手 |
